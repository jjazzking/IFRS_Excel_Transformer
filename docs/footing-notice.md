# [Notion 공지 초안] 기준서 footing 검수 협조 요청

> 아래 본문을 Notion 페이지에 그대로 붙여넣으면 됩니다. 대괄호 부분만 채우세요.

---

## 기준서 footing 검수 — 1인 6시간, 9/11(목) 마감

조서 추출기가 쓰는 회계기준서 DB는 기준서 HWP 원문을 파싱해서 만들었습니다.
**기준서 40건 · 문단 3,661건.** 배포 전에 이 데이터가 원문과 맞는지 확인해야 하는데,
전수로 읽으면 1인 900문단이라 현실적으로 불가능합니다.

그래서 **기계가 잡을 수 있는 결함은 이미 전수로 걸러냈습니다.** 여러분이 볼 것은 두 가지뿐입니다.

- **확인지점 233곳** — 기계가 "이상하다"고 짚었지만 정상인지 오류인지는 사람만 판정할 수 있는 지점
- **표본 200문단** — 기계가 놓친 결함이 있는지 보려고 무작위로 뽑은 문단 (기준서당 5개)

합쳐서 433건, 전체 문단의 11.8%입니다. **1인당 기준서 10건 / 약 6시간**이고,
9/9~9/11 사흘간 하루 2시간이면 끝납니다.

### 자동 검증이 이미 찾아낸 것 (사람이 전수로 읽어야 나올 종류)

- 제1032호 문단 5·6·7 **누락** — 문단 4 다음이 곧바로 8
- 제1032호 문단 100에 부록 적용지침 전체(10,238자)가 **한 문단으로 병합**
- 제1116호 문단 2 본문 끝에 다음 절 제목 `적용` **유입**
- 제1007호 문단 52 끝줄 `시행일고과 경과 규정` — 제목이 깨진 채 섞임

이런 게 하나라도 남아 있으면, 그 문단을 인용한 조서가 그대로 틀립니다.

## 무엇을 하면 되나요

1. 아래 DB에서 **`내 작업` 뷰**를 열면 본인 담당 행만 나옵니다.
2. 각 행의 `검출근거` 를 보고, **원문에서 해당 문단을 찾아 대조**합니다.
3. `판정` 을 넷 중 하나로 고릅니다. **수정안을 쓰실 필요는 없습니다.**

   | 판정 | 언제 |
   | --- | --- |
   | `정상` | 원문과 같음 (자동검증이 과하게 잡은 경우) |
   | `오류` | 원문과 다름 → `수정내용` 에 무엇이 어떻게 달라야 하는지 **한 줄** |
   | `판본차이` | 내가 본 원문과 다르지만, 판본 차이일 수 있음 |
   | `판단보류` | 원문을 봐도 판단이 안 섬 → 이유를 `비고` 에 한 줄 |

4. `대조출처` 에 **무엇을 보고 대조했는지** 적습니다 (`법인 포털` / `기준원 웹` / `HWP` 등).
   원문은 **각자 편한 것을 보시면 됩니다.** 다만 판본이 다르면 판정도 갈리므로,
   `오류` 로 단정하기 애매하면 `판본차이` 로 두고 넘어가 주세요.
   `판본차이` 로 모인 건은 마감 후 한 판본으로 일괄 확인합니다 —
   **판본을 맞추느라 시간 쓰지 않는 것**이 이 규칙의 목적입니다.
5. 다 본 행은 `상태` 를 `완료` 로 바꿉니다.

### 행 종류별로 보는 법

| 규칙 | 무엇을 보나 | 건당 |
| --- | --- | ---: |
| `SETUP` | 원문을 열고 그 기준서 범위를 확인 (기준서마다 첫 행) | 5분 |
| `NUM_GAP` | 비어 있는 문단번호가 **원문에 실제로 있는지**. 있으면 `오류`, 삭제된 문단이면 `정상` | 10분~ |
| `HEADING_LEAK` | 본문 **마지막 줄**이 본문의 일부인지, 다음 절 제목이 흘러든 것인지 | 2분 |
| `OVERSIZE` | 긴 문단이 원문에서 **정말 한 문단인지**, 여러 문단이 붙은 것인지 | 6분 |
| `SAMPLE` | 본문이 통째로 같은지 / 문단번호가 맞는지 / 앞뒤가 잘리지 않았는지 **세 가지만**. 문장부호·띄어쓰기 차이는 `정상` | 3분 |

# 부록 — Notion DB 만드는 법 (운영자용)

1. **CSV 생성**

   ```bash
   python3 scripts/audit_standards.py --assign 4 --worksheet 기준서_footing_검수.csv
   ```

   473행이 나옵니다 (확인지점 233 + 표본 200 + 착수 40).

2. **Notion 가져오기** — 새 페이지 → `가져오기` → `CSV` → 파일 선택. 표가 DB로 만들어집니다.

3. **속성 타입 바꾸기** (가져오면 전부 텍스트로 들어옵니다)

   | 속성 | 타입 | 선택지 |
   | --- | --- | --- |
   | 항목 | 제목 | — |
   | 상태 | 선택 | 미착수 · 확인중 · 완료 |
   | 담당자 | 사람 | (검수자 1~4 → 실제 사람으로 교체) |
   | 심각도 | 선택 | P1 · P2 · 표본 · 착수 |
   | 기준서 / 규칙 / 대조출처 | 선택 | 값에서 자동 생성 |
   | 예상시간(분) | 숫자 | 합계 표시 켜기 |
   | 판정 | 선택 | 정상 · 오류 · 판본차이 · 판단보류 |
   | 기준서명 · 문단 · 검출근거 · 수정내용 · 비고 | 텍스트 | — |

4. **뷰 3개**

   | 뷰 | 유형 | 필터 · 그룹 |
   | --- | --- | --- |
   | 내 작업 | 표 | 필터 `담당자 = 나` + `상태 ≠ 완료` / 그룹 `기준서` / 정렬 `심각도` |
   | 진행률 | 보드 | 그룹 `상태` / 하위그룹 `담당자` / 예상시간(분) 합계 표시 |
   | 후속조치 | 표 | 필터 `판정` 이 `오류`·`판본차이`·`판단보류` 중 하나 |

5. **마감 후 회수** — `후속조치` 뷰를 CSV로 내보내 개발에 전달합니다.
   `예상시간(분)` 합계와 실제 소요시간을 비교해 다음 회차 계획에 반영합니다.
