# 이사회 의사록 읽기 — 1단계 설계와 PoC (PDF → 정규 데이터 스키마)

이 문서는 **PDF 를 읽어 정규 데이터 스키마를 채우는 데까지만** 다룬다. 엑셀 양식 매핑(2단계)은
스키마가 확정되고 정확도가 측정된 뒤에 시작한다.

**대화전문은 범위에서 뺐다.** 한국 이사회 의사록은 대부분 요약식이라 발언자별 축어록이 거의
없다. 없는 항목을 위해 설계를 복잡하게 만들 이유가 없다. 나중에 상세 의사록을 다루게 되면
의안 아래에 `discussion[]` 을 더하는 것으로 충분하다.

> **2026-09 갱신** — 규칙 전용 PoC 를 만들어 돌렸다. 결론이 설계를 바꿨다. 3장을 먼저 읽어라.

---

## 0. 먼저 걸리는 벽 두 개

기술 선택보다 앞에 오는 제약이다.

### 벽 1 — 이 앱에는 서버가 없다

지금 구조는 GitHub Pages 정적 호스팅이다. 환율은 이 벽을 **미리 받아 커밋하는 방식**으로
피해 갔다 (`scripts/fetch_fx_rates.py`). 의사록은 그럴 수 없다. 사용자가 그 자리에 올리는
파일이므로 미리 받아 둘 대상이 아니다.

| 안 | 파일이 지나가는 길 | 키 | 비용 | 언제 쓰나 |
| --- | --- | --- | --- | --- |
| **A. 브라우저 단독** | 브라우저 밖으로 안 나감 (규칙 전용) 또는 브라우저 → 모델 API 직접 | 없음 / 사용자 키 | 서버비 0 | **규칙 전용이면 이걸로 끝난다** |
| **B. Cloud Run API** | 브라우저 → 우리 서버(메모리) → 모델 API | 서버 환경변수 | 월 수천~수만원 | OCR·요약을 붙일 때 |
| **C. 사내망 폐쇄** | 외부로 안 나감 | 없음 | GPU 장비 | 외부 전송이 불허될 때 |

3장의 측정 결과는 **A 의 문턱을 크게 낮춘다.** 규칙만 쓰는 동안은 파일이 브라우저 밖으로
나가지 않으므로 벽 2 가 아예 성립하지 않는다.

### 벽 2 — 의사록은 미공개 중요정보다

기준서·환율은 공개 자료였다. 이사회 의사록은 아니다. 외부 API 로 보내는 순간 성격이 달라진다.

- **학습 미사용 · 무보존 조건이 걸린 티어**여야 한다. 무료 티어는 대체로 입력이 학습에 쓰일
  수 있으므로 애초에 후보가 아니다.
- **국외 이전** 동의가 필요한지 확인한다. 국내 리전에서 도는 OCR 을 후보에 남겨 둔 이유다.
- 업로드 파일을 **디스크에 쓰지 않는다.** 메모리에서 처리하고 응답 후 버린다. 로그에 본문을
  남기지 않는다.

**이 벽은 외부로 내보내는 것에만 선다.** 규칙 전용 경로는 이 심의를 기다리지 않고 쓸 수 있다.

## 1. 설계의 중심 생각 — 값을 지어내지 않고 원문을 가리킨다

뽑아야 할 항목을 두 부류로 나눈다.

| 부류 | 항목 | 내놓는 것 |
| --- | --- | --- |
| **전사(轉寫)** | 의안내용 원문, 의안제목, 장소, 일시, 각종 인원수, 가결 여부 | **원문의 위치**(문자 구간)만 |
| **판단** | 의안 요약, 재무제표 영향 | 생성한 문장 + 그 근거의 위치 |

전사 항목은 누구도 — 규칙도 모델도 — 글자를 다시 쓰지 않는다. 위치만 받고 실제 글자는
코드가 원문에서 잘라낸다. 이유가 셋이다.

1. **변조가 원천적으로 불가능해진다.** 법적 문서의 원문이 한 글자라도 바뀌면 그 산출물은
   증빙으로 못 쓴다.
2. **모델을 쓸 때 비용이 내려간다.** 출력 토큰은 입력 토큰보다 8배 이상 비싸다. 의안 원문을
   통째로 다시 뱉게 하면 출력이 입력만큼 커진다 (6장).
3. **근거 좌표가 공짜로 따라온다.** 위치를 받았으므로 PDF 하이라이트에 필요한 bbox 를 코드가
   역산할 수 있다.

> **원칙**: 좌표를 묻지 않는다. 텍스트 구간을 받고, 좌표는 우리가 되찾는다.
> 되찾기에 실패한 구간은 **환각 신호**로 취급해 그 필드를 `검토 필요` 로 내린다.

## 2. 파이프라인 6단계

```
PDF ─① 페이지 분류 ─② 텍스트화 ─③ 좌표계 만들기 ─④ 의안 쪼개기 ─⑤ 필드 뽑기 ─⑥ 검증 → JSON
        텍스트냐 스캔이냐    (경로 분기)    문자 오프셋↔bbox     규칙        규칙(+모델)   교차검증
```

| 단계 | 무엇을 | 어디에 |
| --- | --- | --- |
| ① 페이지 분류 | 페이지별로 텍스트 레이어 유무를 판정. 스캔 페이지만 OCR 로 보낸다 | `minutes_text.py` |
| ② 텍스트화 | 텍스트 경로는 PyMuPDF 로 낱말+bbox. **비용 0, 정확도 100%** | `minutes_text.py` |
| ③ 좌표계 | `{본문 문자열, 오프셋 → 낱말 → bbox}`. 이후 모든 근거가 여기 매달린다 | `minutes_text.py` |
| ④ 의안 쪼개기 | `제N호 의안` 류 정규식. 싸고 결정론적이고 재현된다 | `minutes_rules.py` |
| ⑤ 필드 뽑기 | 일시·장소·인원수·제목·가결여부·금액·기준서 후보 | `minutes_rules.py` |
| ⑥ 검증 | 정족수 산술, 번호 연속성, 찬반 합계 — 모델 없이 돈다 | `parse_minutes.py` |

**페이지 단위 분기가 비용의 절반을 가른다.** 한글·워드에서 출력한 의사록은 텍스트 레이어가
이미 있다. 실무 문서는 대개 혼재한다 — 본문은 텍스트본, 날인 페이지만 스캔본. 이런 페이지에
OCR 을 돌리는 건 돈과 정확도를 동시에 버리는 일이다.

③에서 **길이를 보존하는 정규화만** 한다. 전각 숫자를 반각으로 바꾸는 건 되고, 공백을 없애는
건 안 된다. 오프셋이 한 글자라도 밀리면 근거 추적이 전부 무너진다.

## 3. 규칙만으로 어디까지 되는가 — 측정했다

`scripts/parse_minutes.py` 는 **모델을 부르지 않는다.** API 키도, 네트워크도, 비용도 없다.
합성 표본 4건(`scripts/make_sample_minutes.py`)으로 채점한 결과다.

```
python3 scripts/make_sample_minutes.py -o samples/minutes
python3 scripts/parse_minutes.py samples/minutes -o out/minutes --print
python3 scripts/eval_minutes.py samples/minutes out/minutes --detail
```

| 필드 | 규칙 전용 정확도 | 목표 | 판정 |
| --- | ---: | ---: | --- |
| 일시(날짜) · 개회시각 | 100% | 98% / 90% | 통과 |
| 장소 | 100% | 95% | 통과 |
| 총·출석 이사 수 | 100% | 98% | 통과 |
| 총·출석 감사위원 수 | 100% | 98% | 통과 |
| 의안제목 | 90% | 95% | 미달 |
| 가결 여부 | 90% | 95% | 미달 |
| 의안 경계 | 75% | 95% | 미달 |
| 폐회시각 | 75% | 90% | 미달 |
| **전체** | **93%** | | |

**틀린 4건이 전부 한 곳에서 나왔다 — 스캔 페이지.** 표본 3번의 2쪽이 이미지라 규칙이 거기
있는 의안 하나와 폐회시각을 통째로 놓쳤다. 텍스트 레이어가 있는 표본 3건은 **모든 필드
100%** 다.

### 그래서 AI 를 안 붙이는 건 가능한가

**대체로 가능하다.** 정확히 두 자리에서만 못 한다.

| | 규칙으로 되나 | 왜 |
| --- | --- | --- |
| 일시 · 장소 · 인원수 4종 | **된다** | 라벨 서식이 강하다. `일    시 :` 처럼 글자를 벌려 써도 잡는다 |
| 의안번호 · 제목 · 경계 | **된다** | `제N호 의안` / `의안 제N호` / `보고사항 제N호` 패턴 |
| 의안내용 원문 | **된다** | 경계만 맞으면 잘라내기다. 규칙이 오히려 정확하다 |
| 가결 여부 | **된다** | `원안대로 가결` · `부결` · `만장일치` 같은 정형구 |
| 찬반 표수 · 금액 | **된다** | 숫자 패턴 |
| 재무제표 영향 **후보** | **된다** | 키워드 → 기준서 매핑표. 저장소의 문단 3,661건을 재사용 |
| **스캔 페이지 글자 읽기** | **안 된다** | OCR 이 필요하다. 그림에는 글자가 없다 |
| **의안 요약 문장 쓰기** | **안 된다** | 생성이다. 지금은 결의 문장을 **발췌**한다 |
| 재무제표 영향 **판단** | 안 된다 (할 생각도 없다) | 사람이 판단한다. 규칙은 어디를 볼지까지만 좁힌다 |

두 가지 모두 **선택적으로 붙이면 되는 것**이지 전제가 아니다.

- **OCR 은 스캔 페이지가 있을 때만** 부른다. 텍스트본만 다루는 회사라면 영영 필요 없다.
  지금은 해당 페이지를 `SCAN_PAGE` 로 보고하고 멈춘다 — 조용히 빈칸으로 두지 않는다.
- **요약은 발췌로 갈음**한다. `method: "extractive"` 로 표시하므로 생성된 문장과 섞이지
  않는다. 사람이 검토할 때 어차피 그 결의 문장을 본다.

### 규칙을 먼저 두는 것의 진짜 이득

싸다는 것보다 이쪽이 크다.

1. **틀리면 왜 틀렸는지 보인다.** 모든 값에 `rule` 이름이 붙는다 (`COUNT_BOTH`, `DATE_LABEL`).
   틀린 값을 보면 어느 정규식을 고칠지 바로 안다. 고치면 그다음부터 항상 맞는다.
2. **재현된다.** 같은 PDF 는 언제 돌려도 같은 JSON 이다. 감사 산출물에서 이건 선택이 아니다.
3. **벽 2 를 기다리지 않는다.** 파일이 어디로도 나가지 않는다.
4. **모델을 붙일 때 비교 대상이 생긴다.** 93% 라는 바닥이 있어야 모델이 실제로 나은지 안다.

## 4. 정규 데이터 스키마

정의한 항목을 **문서 레벨 / 의안 레벨**로 나눈다. 실제 출력은 `out/minutes/*.json` 에서 볼 수 있다.

```
MinutesDocument
├ schemaVersion: 1                     스키마가 바뀌어도 예전 산출물을 읽을 수 있게
├ extraction: { method: 'rules', llmUsed: false, ruleVersion }
├ source: { fileName, pageCount, pageKinds: ('text'|'scan')[], scanPages }
├ meeting
│  ├ heldAt        일시   { date, startTime, endTime, evidence }
│  └ place         장소   { value, rule, evidence }
├ attendance
│  ├ directors        { total, present, evidence }     총 이사 수 / 출석 이사 수
│  └ auditCommittee   { total, present, evidence }     총 감사위원 수 / 출석 감사위원 수
├ agenda[]
│  ├ number        의안번호  { ordinal, evidence }
│  ├ kind          결의 | 보고
│  ├ title         의안제목
│  ├ body          의안내용 원문   ← 구간을 잘라낸 것
│  ├ summary       { method: 'extractive'|'generated', value, evidence }   가결 여부 포함
│  ├ resolution    { value: 원안가결|수정가결|가결|부결|보류|해당없음, votes, unanimous, evidence }
│  └ fsImpact      재무제표 영향 — **사전 검토 후보만**
│     ├ hasImpact  판단필요 | 확인불가      ← '있음/없음' 은 규칙이 말하지 않는다
│     ├ standards[]  관련 기준서 후보       ← 기존 3,661 문단 자산 재사용
│     ├ amounts[]    금액 + 근거
│     └ note        "규칙이 고른 검토 후보다. 영향 여부는 사람이 판단한다."
└ review           { flags[], needsReviewCount, p1Count }
```

**모든 필드에 붙는 근거 구조**는 하나로 통일한다.

```
Evidence = { page, start, end, text, bbox[], source: 'text'|'ocr'|'model' }
```

`text` 는 **코드가 원문에서 잘라낸 것**이지 누가 다시 쓴 것이 아니다 (1장 원칙).

### 짚어 둘 두 가지

- **인원수는 두 군데서 온다.** 본문 서술("재적이사 7명 중 6명 출석")과 참석자 명단. 규칙은
  서술 쪽을 읽고, `사외이사 3명 중 3명 출석` 같은 **소집단 수를 총수로 착각하지 않도록**
  `사외·사내·상근·비상근` 이 앞에 붙은 것은 건너뛴다. 문서 안에서 값이 갈리면
  `COUNT_CONFLICT` 로 표시하고 어느 쪽도 고르지 않는다.
- **재무제표 영향은 이 저장소에서만 가능한 항목이다.** 의안에서 `유상증자`·`사채 발행`·
  `지급보증`·`특수관계자` 같은 말을 잡아 관련 기준서를 후보로 붙인다. 사람은 판단만 하면 된다.
  매핑표는 `minutes_rules.IMPACT_TRIGGERS` 한 곳에 있고, 현장에서 쓰다가 늘리면 된다.

## 5. 무엇을 믿을 수 있다고 할 것인가 — 검증

**스스로 매긴 신뢰도는 쓰지 않는다.** 근거가 없는 숫자다. 대신 서로 맞아야 하는 값을 맞춰 본다.

| 규칙 | 무엇을 확인 | 등급 |
| --- | --- | --- |
| `SCAN_PAGE` | 이미지 페이지가 있는가 — 규칙이 읽지 못한 구간이다 | P1 |
| `COUNT_CONFLICT` | 인원수가 문서 안에서 여러 값으로 읽히는가 | P1 |
| `QUORUM_RANGE` | 출석 수 ≤ 총 수 | P1 |
| `QUORUM_LEGAL` | 이사 과반수 출석 (상법 391조 1항; 정관 가중 가능) | P1 |
| `VOTE_SUM` | 찬성+반대+기권 ≤ 출석 이사 수 | P1 |
| `AGENDA_NONE` | 의안을 하나도 못 찾았는가 | P1 |
| `RESOLUTION_MISSING` | 가결 여부를 못 읽었는가 | P1 |
| `AGENDA_SEQ` | 의안번호가 1부터 이어지는가 — 페이지 누락 신호 | P2 |
| `TIME_ORDER` | 폐회 > 개회 | P2 |
| `SPAN_OVERLAP` | 의안 구간이 겹치는가 | P2 |
| `EMPTY_REQUIRED` | 필수 항목 중 빈 것 | P2 |

전부 모델 없이 돈다. 화면의 `검토 필요만 보기` 필터가 이 결과를 그대로 쓴다.
`scripts/audit_standards.py` 가 기준서에 하던 일과 같은 역할이다.

## 6. 얼마나 드는가

### 규칙 전용

**0원.** 네트워크도 타지 않는다. 4건 처리에 1초 남짓이다.

### 모델을 붙인다면 (스캔 페이지 OCR · 요약 생성)

의사록 1건 = 10 페이지, 그중 스캔 2 페이지로 잡는다.

| 항목 | 건당 |
| --- | ---: |
| OCR — 스캔 2페이지만 | 몇 원~수십 원 |
| 요약 생성 — 의안 3건, 입력은 해당 구간만 | 10원대 |
| 의안 원문까지 모델이 다시 뱉게 하는 경우 | 50원 안팎 (쓰지 않는다, 1장) |
| **합** | **수십 원** |

단가는 반드시 재확인할 것. 자릿수 감각용이다. **연 1,000건이어도 10만원을 넘기 어렵다.**
API 비용은 이 기능의 제약이 아니다.

### 진짜 비용은 사람의 검증 시간이다

판단 기준은 하나로 둔다.

> 수작업으로 의사록 1건을 스키마에 옮기는 데 걸리는 시간 대비,
> **이 도구의 결과를 검증·수정하는 시간이 1/3 이하**인가.

## 7. 코드 구조

### 지금 있는 것 (규칙 전용 PoC, 화면 없음)

scripts/

  parse_minutes.py         오케스트레이션 + ⑥ 교차검증 + JSON 출력  ← CLI

  make_sample_minutes.py   합성 표본 + 정답 만들기                   ← CLI
```

`fetch_fx_rates.py` + `smbs.py` 와 같은 모양이다 — 읽는 모듈과 도는 스크립트를 나눈다.
화면보다 스크립트를 먼저 만든 이유는 8장에 있다.

### 나중에 붙일 것

```
src/workspaces/
  registry.ts              ← { id: 'minutes', name: '의사록 읽기' } 한 줄
  MinutesWorkspace.tsx     ← 좌 PDF · 우 스키마. 기존 3존 레이아웃 훅 재사용
src/components/minutes/
  PdfViewer.tsx            pdfjs-dist 캔버스 + bbox 하이라이트
  SchemaInspector.tsx      필드별 값·근거·등급, `검토 필요만 보기`
  EvidenceLink.tsx         필드 ↔ PDF 양방향 이동

파이썬 판으로 정확도를 올려 두고, 확정된 규칙만 TypeScript 로 옮기면 브라우저에서 돈다 —
그러면 벽 1 과 벽 2 를 둘 다 지나간다.

## 8. 순서와 판단 게이트

| 단계 | 하는 일 | 상태 |
| --- | --- | --- |
| 0. 표본 | 서식 변형을 담은 표본 + 정답 | **됨** — 합성 4건. 실제 의사록으로 갈아야 한다 |
| 1. 읽기 | ①②③ 텍스트·좌표 | **됨** |
| 2. 뽑기 | ④⑤⑥ 규칙 + 검증 | **됨** — 전체 93%, 텍스트 페이지만 보면 100% |
| 3. 채점 | 필드별 정확도 | **됨** — `eval_minutes.py` |
| **4. 실제 표본** | 진짜 의사록 20건으로 다시 채점 | **다음** — 여기서 규칙의 진짜 성적이 나온다 |
| 5. OCR | 스캔 페이지에만. 엔진 비교 | 4 에서 스캔 비율이 확인되면 |
| 6. 보안 | 외부 전송이 필요할 때만 | 5 가 필요할 때 |
| 7. 화면 | 작업대 붙이기 | 4 통과 후 |
| 8. 엑셀 | (2단계 — 이 문서 범위 밖) | 7 통과 후 |

**4단계가 지금 가장 중요하다.** 합성 표본은 내가 만든 서식만 담고 있어 규칙에 유리하다.
실제 의사록에서 몇 %가 나오는지가 진짜 답이고, 거기서 떨어지는 필드만 손보면 된다.

### OCR 이 필요한지 판정하는 법

실제 표본 20건을 넣고 `SCAN_PAGE` 표시가 몇 건에 붙는지만 세면 된다. 텍스트 레이어가
대부분이면 OCR 은 영영 필요 없고, 벽 2 도 서지 않는다.

## 9. 미리 알고 있는 위험

| 위험 | 어디서 터지나 | 완화 |
| --- | --- | --- |
| **합성 표본의 착시** | 3장의 100% | 실제 의사록으로 다시 잰다 (8장 4단계) |
| **회사별 서식 편차** | 의안 표기, 인원수 서술 | 규칙은 한 곳에 모여 있다. 틀린 건마다 규칙을 늘린다 |
| **소집단 수 오독** | `사외이사 3명 중 3명 출석` | 앞말 차단 + `COUNT_CONFLICT` 표시 |
| **스캔 페이지 묵살** | 날인 페이지, 스캔본 | `SCAN_PAGE` P1. 조용히 넘어가지 않는다 |
| **원문 변조** | 의안 원문 | 위치 방식(1장). 글자를 다시 쓰지 않는다 |
| **요약을 사실로 오인** | `summary` | `method: extractive` 로 발췌임을 표시 |
| **스키마 변경** | 2단계 엑셀 매핑 확정 시 | `schemaVersion` + 마이그레이션 |
| **보안** | 외부 전송 경로에만 | 규칙 전용 경로는 해당 없음 |

법적 문서라 **누락보다 조용한 오탐이 훨씬 비싸다.** 확신이 없으면 빈칸으로 두고 `검토 필요`
를 다는 쪽이 항상 맞다. 화면도 그렇게 설계한다 — 채워진 값이 아니라 **비어 있고 표시된 값**이
사용자를 안내한다.

## 10. 지금 결정해야 할 것

1. **실제 의사록 20건을 어떻게 확보하는가.** 규칙 전용이면 파일이 밖으로 나가지 않으므로
   보안 승인 없이도 로컬에서 돌릴 수 있다. 이게 지금 유일한 병목이다.
2. **다루는 문서 중 스캔본 비율.** OCR 을 붙일지 말지가 여기서 갈린다.
3. **요약을 발췌로 둘 것인가, 생성으로 올릴 것인가.** 발췌로 충분하다면 이 기능은 끝까지
   모델 없이 간다.
