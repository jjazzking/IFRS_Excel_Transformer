# 이사회 의사록 읽기 — 1단계 설계 (PDF → 정규 데이터 스키마)

이 문서는 **PDF 를 읽어 정규 데이터 스키마를 채우는 데까지만** 다룬다. 엑셀 양식 매핑(2단계)은
스키마가 확정되고 정확도가 측정된 뒤에 시작한다. 코드는 아직 쓰지 않았다. 여기서 정할 것은
셋이다 — **어디서 도는가 · 무엇으로 읽는가 · 무엇을 믿을 수 있다고 할 것인가.**

---

## 0. 먼저 걸리는 벽 두 개

기술 선택보다 앞에 오는 제약이다. 이 둘이 정해지지 않으면 아래 설계는 전부 가정이다.

### 벽 1 — 이 앱에는 서버가 없다

지금 구조는 GitHub Pages 정적 호스팅이다. 환율은 이 벽을 **미리 받아 커밋하는 방식**으로
피해 갔다 (`scripts/fetch_fx_rates.py`). 의사록은 그럴 수 없다. 사용자가 그 자리에서 올리는
파일이므로 미리 받아 둘 대상이 아니다. 선택지는 셋이다.

| 안 | 파일이 지나가는 길 | 키 | 비용 | 언제 쓰나 |
| --- | --- | --- | --- | --- |
| **A. 브라우저 단독** | 브라우저 → 모델 API 직접 | 사용자가 자기 키를 넣고 브라우저에 보관 | 서버비 0 | PoC · 소수 사용자 |
| **B. Cloud Run API** (권장 도착지) | 브라우저 → 우리 서버(메모리) → 모델 API | 서버 환경변수 | 월 수천~수만원 | 정식 배포 |
| **C. 사내망 폐쇄** | 외부로 안 나감 | 없음 | GPU 장비 | 외부 전송이 불허될 때 |

`server.js`(express)와 `metadata.json` 의 `MAJOR_CAPABILITY_SERVER_SIDE_GEMINI_API` 는 이미
B 를 향해 있다. **A 로 정확도를 증명하고 B 로 배포**하는 순서를 제안한다. C 는 정확도가 한
단계 떨어지므로(아래 3-1 표) 보안 심의 결과가 그렇게 나올 때만 간다.

### 벽 2 — 의사록은 미공개 중요정보다

기준서·환율은 공개 자료였다. 이사회 의사록은 아니다. 외부 API 로 보내는 순간 성격이 달라진다.

- **학습 미사용 · 무보존 조건이 걸린 티어**여야 한다. 무료 티어는 대체로 입력이 학습에
  쓰일 수 있으므로 애초에 후보가 아니다. 유료 티어 또는 기업용 엔드포인트만 검토한다.
- **국외 이전** 동의가 필요한지 확인한다. 국내 리전에서 도는 OCR(네이버 CLOVA 등)을
  후보에 남겨 둔 이유가 이것이다.
- 업로드 파일을 **디스크에 쓰지 않는다** — 메모리에서 처리하고 응답 후 버린다. 로그에 본문을
  남기지 않는다. 이건 설계 초기에 못 박아야 나중에 뒤집지 않는다.

법인 승인 요청서에 붙일 문장은 PoC 결과가 나온 뒤에 쓴다. **"정확도 이만큼, 건당 원가 이만큼,
파일은 이 경로로만 지나가고 저장되지 않음"** 세 줄이면 된다.

## 1. 설계의 중심 생각 — 모델은 가리키게 하고, 글자는 코드가 옮긴다

가장 중요한 결정이다. 뽑아야 할 항목을 두 부류로 나눈다.

| 부류 | 항목 | 모델이 내놓는 것 |
| --- | --- | --- |
| **전사(轉寫)** | 의안내용 원문, 대화전문, 장소, 일시, 각종 인원수 | **원문의 위치**(페이지 + 문자 구간)만 |
| **판단** | 의안 요약, 가결 여부, 재무제표 영향 | 생성한 문장 + 그 근거의 위치 |

전사 항목을 모델이 다시 타이핑하게 두지 않는다. 이유가 셋이다.

1. **변조가 원천적으로 불가능해진다.** 법적 문서의 원문이 한 글자라도 바뀌면 그 산출물은
   증빙으로 못 쓴다. 위치만 받고 실제 글자는 코드가 원문에서 잘라내면 이 위험이 0 이 된다.
2. **비용이 1/3~1/4 로 떨어진다.** 출력 토큰은 입력 토큰보다 8배 이상 비싸다. 대화 전문을
   통째로 다시 뱉게 하면 출력이 입력만큼 커진다 (아래 6장 계산).
3. **근거 좌표가 공짜로 따라온다.** 위치를 받았으므로 PDF 하이라이트에 필요한 bbox 를
   코드가 역산할 수 있다. 모델에게 좌표를 물어보면 안 된다 — 그건 모델이 가장 못하는 일이다.

> **원칙**: 모델에게 좌표를 묻지 않는다. 텍스트 구간을 받고, 좌표는 우리가 되찾는다.
> 되찾기에 실패한 구간은 **환각 신호**로 취급해 그 필드를 `검토 필요` 로 내린다.

## 2. 파이프라인 6단계

```
PDF ─① 페이지 분류 ─② 텍스트화 ─③ 좌표계 만들기 ─④ 의안 쪼개기 ─⑤ 필드 뽑기 ─⑥ 되찾기·검증 → JSON
        텍스트냐 스캔이냐    (경로 분기)    문자 오프셋↔bbox    규칙 우선      모델 호출    앵커링 + 교차검증
```

### ① 페이지 분류 — 비용의 절반이 여기서 갈린다

한글·워드에서 출력한 의사록은 **텍스트 레이어가 이미 있다.** 이런 페이지에 OCR 을 돌리는 건
돈과 정확도를 동시에 버리는 일이다. 실무 문서는 대개 혼재한다 — 본문은 텍스트본, 날인·서명
페이지만 스캔본. 그래서 **페이지 단위로** 판정한다.

판정 규칙: 그 페이지에서 추출된 글자 수가 임계값 미만이거나, 글자 상자 면적이 페이지의
극히 일부만 덮으면 이미지 페이지로 본다. 회전된 페이지는 여기서 각도를 바로잡는다.

### ② 텍스트화 — 두 경로

- **텍스트 경로**: `pdfjs-dist`(브라우저) 또는 `PyMuPDF`(배치). 낱말 단위 텍스트와 bbox 를
  그대로 준다. **비용 0, 정확도 100%.**
- **스캔 경로**: OCR API. 낱말 단위 bbox 와 낱말별 신뢰도를 주는 엔진만 후보다
  (페이지 통짜 텍스트만 주는 엔진은 근거 추적을 못 하므로 탈락).

### ③ 좌표계 만들기 — 나중에 전부 여기에 매달린다

페이지마다 `{ 정규화된 본문 문자열, 문자 오프셋 → 낱말 인덱스 → bbox }` 를 만든다. 이후 모든
근거는 `(page, startOffset, endOffset)` 하나로 표현된다. 모델에 보내는 본문도, 되받은 위치를
해석하는 기준도 전부 이 문자열이다. **줄바꿈·공백·전각문자 정규화를 여기서 한 번만** 하고,
원본 오프셋과의 대응표를 들고 간다.

### ④ 의안 쪼개기 — 규칙을 먼저, 모델은 나중에

한국 이사회 의사록의 의안 표기는 패턴이 강하다 (`제1호 의안`, `제 1 호 의안`, `의안 1.`,
`제1호 안건`, `부의안건 1`). **정규식으로 먼저 자른다.** 싸고 결정론적이고 재현된다.
규칙이 아무것도 못 찾은 문서만 모델에게 경계를 묻는다. 이 분기 하나로 호출 수가 크게 준다.

쪼개진 뒤에는 의안별로 병렬 호출이 가능해지고, 긴 문서에서도 컨텍스트가 짧게 유지된다.
화면에서 **의안 단위로 결과가 차례로 채워지는** 것도 여기서 나온다.

### ⑤ 필드 뽑기 — 두 종류의 호출

| 호출 | 대상 | 모델 급 | 출력 |
| --- | --- | --- | --- |
| 문서 메타 1회 | 앞 1~2 페이지 | 저가(Flash급) | 일시·장소·인원수 + 각각의 위치 |
| 의안별 N회 | 해당 구간만 | 원문/대화는 저가, 요약·재무영향은 상위(Pro급) | 위치 배열 + 생성 문장 |

**JSON 스키마를 강제한 구조화 출력**(`responseSchema` / structured output)만 쓴다. 자유 형식
JSON 을 받아 파싱하는 방식은 쓰지 않는다. 온도는 0.

### ⑥ 되찾기·검증

받은 위치를 ③의 좌표계에 대고 bbox 를 역산한다. 모델이 위치 대신 짧은 인용문을 준 경우에는
정규화 후 문자열 매칭으로 구간을 찾는다 — **못 찾으면 그 필드는 신뢰하지 않는다.**
그 다음 5장의 교차검증 규칙을 돌린다.

## 3. 무엇으로 읽는가 — 도구 후보

### 3-1. OCR (스캔 페이지에만 쓴다)

| 후보 | 한국어 | 낱말 bbox | 데이터 위치 | 대략 단가 | 판단 |
| --- | --- | --- | --- | --- | --- |
| **Google Cloud Vision** (문서 텍스트) | 좋음 | 있음 | 국외 | 페이지당 수원대 | 1순위 — 싸고 무난 |
| **Naver CLOVA OCR** | 최상급(도장·표에 강함) | 있음 | **국내** | 건당 과금, 더 비쌈 | 국외 이전이 막힐 때 1순위 |
| **Upstage Document Parse** | 한국어 문서 특화, 표를 구조로 반환 | 있음 | 국내/국외 선택 | 페이지당 | 표가 많은 의사록에서 재검토 |
| Google Document AI | 좋음 | 있음 | 국외 | Vision 의 수배 | 레이아웃까지 필요할 때만 |
| PaddleOCR / Tesseract | 중~하 | 있음 | **로컬** | 장비값만 | 벽1의 C안 전용 |

**시작은 Vision 하나로 충분하다.** OCR 엔진은 ②단계 뒤에 갈아 끼울 수 있게 인터페이스
하나(`ocr(pageImage) → Word[]`)로 감싸 둔다. PoC 에서 스캔본 10건을 두 엔진으로 돌려
비교하면 선택이 끝난다.

### 3-2. 언어 모델

저장소에는 `@google/genai` 가 이미 들어와 있고 `metadata.json` 이 서버측 Gemini 호출을
선언하고 있다. **기본은 Gemini**로 간다 — 배선이 이미 되어 있고, 멀티모달이라 스캔 페이지를
이미지째로 넘기는 보조 경로가 열려 있으며, 구조화 출력을 지원한다.

호출은 급을 나눈다. 의안 경계·문서 메타·전사 위치처럼 **정답이 문서 안에 있는 일**은 저가
모델로 충분하다. 요약·가결 여부·재무제표 영향처럼 **판단이 들어가는 일**만 상위 모델로 올린다.
이 분리가 6장 원가표의 전제다.

모델은 한 곳(`src/lib/minutes/llm.ts`)에서만 부르게 하고 호출부는 인터페이스에만 의존시킨다.
정확도·단가 비교로 나중에 다른 제공자로 바꿀 수 있어야 한다.

### 3-3. PDF 화면

`pdfjs-dist` 하나면 된다. 페이지를 캔버스로 그리고 그 위에 bbox 하이라이트 레이어를 얹는다.
텍스트 추출과 화면 렌더가 같은 라이브러리에서 나오므로 좌표계가 어긋나지 않는다. (지금
`package.json` 에 없으므로 추가 대상.)

## 4. 정규 데이터 스키마

정의한 12개 항목을 **문서 레벨 / 의안 레벨**로 나눈다. 반복되는 것은 의안 레벨이다.

```
MinutesDocument
├ schemaVersion: 1                     스키마가 바뀌어도 예전 산출물을 읽을 수 있게
├ source: { fileName, pageCount, pageKinds: ('text'|'scan')[] }
├ meeting
│  ├ heldAt        일시   { raw, date, startTime?, endTime? }
│  └ place         장소   { raw }
├ attendance
│  ├ directors        { total, present }        총 이사 수 / 출석 이사 수
│  ├ auditCommittee   { total, present }        총 감사위원 수 / 출석 감사위원 수
│  └ roster?          [{ name, title, role, attended, byProxy }]   있으면 담는다
├ agenda[]
│  ├ number        의안번호  { raw, ordinal }
│  ├ title         의안제목
│  ├ body          의안내용 원문        → 위치 참조
│  ├ discussion[]  대화전문  [{ speaker, speech → 위치 참조 }]
│  ├ summary       요약 + 가결 여부     { text, resolution: 가결|부결|보류|원안가결|수정가결|해당없음,
│  │                                      votes?: { for, against, abstain }, 기권·제척 사유 }
│  └ fsImpact      재무제표 영향(AI 사전검토)
│     ├ hasImpact: 있음|없음|판단필요
│     ├ reasoning  왜 그렇게 봤는지
│     ├ accounts[] 영향받을 계정·금액·시기
│     └ standards[] 관련 기준서 문단 후보     ← 기존 3,661 문단 자산 재사용
└ review           { flags[], needsReviewCount }
```

**모든 필드에 붙는 근거 구조**는 하나로 통일한다.

```
Evidence = { page, start, end, text, bbox[], confidence, source: 'text'|'ocr'|'model' }
```

- `text` 는 **코드가 원문에서 잘라낸 것**이지 모델이 쓴 것이 아니다 (1장 원칙).
- `source: 'model'` 은 생성된 판단 필드에만 붙고, 그 필드도 근거 구간은 별도로 가리킨다.

### 짚어 둘 세 가지

- **대화전문은 없는 문서가 더 많다.** 한국 의사록은 요약식(`…에 대해 논의한 후 전원 찬성으로
  가결함`)이 다수고, 발언자별 축어록은 상세 의사록에서만 나온다. 없을 때 빈 배열이 정상이고,
  문서 단위로 `style: 요약식|축어록` 플래그를 둬서 **없는 걸 만들어내지 않게** 한다.
- **인원수는 두 군데서 온다.** 본문의 서술("재적이사 7명 중 6명 출석")과 참석자 명단. 둘 다
  뽑아서 대조한다 (5장).
- **재무제표 영향은 이 저장소에서만 가능한 항목이다.** 의안 요약을 검색어로 기준서 문단을
  찾아 후보로 붙이면, 사람은 판단만 하면 된다. `docs/roadmap.md` 의 5번(논점 메모 초안)과
  같은 계열이고, 여기서 먼저 검증해 볼 수 있다.

## 5. 무엇을 믿을 수 있다고 할 것인가 — 검증

**모델이 스스로 매긴 신뢰도는 쓰지 않는다.** 근거가 없는 숫자다. 대신 셋을 합친다.

| 출처 | 무엇을 보는가 |
| --- | --- |
| 앵커링 성공 여부 | 되찾기에 실패한 구간 = 환각 신호 → 즉시 `검토 필요` |
| OCR 낱말 신뢰도 | 스캔 페이지에서 그 구간에 걸친 낱말들의 최저 신뢰도 |
| 교차검증 규칙 | 아래 표 |

### 교차검증 규칙 (결정론적, 값싸고 잘 잡는다)

| 규칙 | 무엇을 확인 | 걸리면 |
| --- | --- | --- |
| `QUORUM_RANGE` | 출석 수 ≤ 총 수, 둘 다 0 초과 | P1 |
| `QUORUM_ROSTER` | 명단의 출석자 수 == 서술된 출석 이사 수 | P1 |
| `QUORUM_LEGAL` | 이사 과반수 출석 (상법 391조 1항; 정관 가중 가능) | P1 — 성립 여부 자체가 의심 |
| `VOTE_SUM` | 찬성+반대+기권 ≤ 출석 수 | P1 |
| `AGENDA_SEQ` | 의안번호가 1부터 빠짐없이 이어지는가 | P2 — 페이지 누락 신호 |
| `DATE_FORMAT` | 일시가 실제 날짜로 파싱되는가, 폐회 > 개회 | P2 |
| `SPAN_OVERLAP` | 의안 구간끼리 겹치지 않는가 | P2 |
| `EMPTY_REQUIRED` | 필수 12항목 중 빈 것 | P2 |

이 규칙들은 모델 없이 돈다. 화면의 `검토 필요만 보기` 필터가 이 결과를 그대로 쓴다.
`scripts/audit_standards.py` 가 기준서에 하던 일과 같은 역할이다.

## 6. 얼마나 드는가

의사록 1건 = **10 페이지**로 잡는다(첨부 제외 기준의 대략적 중앙값).

### 토큰

| 항목 | 텍스트본 | 스캔본 |
| --- | ---: | ---: |
| 입력 (본문 + 프롬프트) | 약 15k | 약 15k |
| 출력 — **위치 방식** (1장) | 약 2k | 약 2k |
| 출력 — 전문 재출력 방식 | 약 12k | 약 12k |

### 건당 원가 (단가는 반드시 재확인할 것 — 아래는 자릿수 감각용)

| 조합 | 건당 | 비고 |
| --- | ---: | --- |
| 저가 모델 + 위치 방식 | **10원대** | 의안 경계·메타·전사 |
| 저가 모델 + 전문 재출력 | 50원 안팎 | 출력이 8배 비싸서 4배 차이 |
| 상위 모델 + 위치 방식 | 50원 안팎 | 요약·재무영향만 여기로 |
| **권장 혼합** (전사는 저가·판단은 상위) | **30~80원** | |
| OCR 추가 (스캔 10p) | +20~100원 | 엔진에 따라 |

**결론: 건당 100원 내외. 연 1,000건이면 10만원대다.** API 비용은 이 기능의 제약이 아니다.

### 진짜 비용은 사람의 검증 시간이다

이 문서 전체가 검증 시간을 줄이는 데 맞춰져 있는 이유다. 판단 기준은 하나로 둔다.

> 수작업으로 의사록 1건을 스키마에 옮기는 데 걸리는 시간 대비,
> **이 도구의 결과를 검증·수정하는 시간이 1/3 이하**인가.

여기 못 미치면 만들 이유가 없고, 미치면 API 비용은 논의 대상이 아니다.

src/workspaces/
  registry.ts              ← { id: 'minutes', name: '의사록 읽기', status: 'preparing' } 한 줄
  MinutesWorkspace.tsx     ← 좌 PDF · 우 스키마. 기존 3존 레이아웃 훅 재사용

  PdfDropZone.tsx          업로드·드래그

  SchemaInspector.tsx      필드별 값·근거·등급, `검토 필요만 보기` 필터

  schema.ts                타입 + 런타임 검증 + schemaVersion
  pageClassify.ts          ① 텍스트/스캔 판정, 회전 보정
  pdfText.ts               ② 텍스트 경로 — 낱말 + bbox
  ocr.ts                   ② 스캔 경로 — 엔진 교체 가능한 인터페이스 하나
  anchorIndex.ts           ③ 오프셋 ↔ bbox 좌표계
  agendaSplit.ts           ④ 정규식 우선, 실패 시 모델
  prompt.ts                ⑤ 구조화 출력 스키마 + 예시

## 8. 순서와 판단 게이트

| 단계 | 하는 일 | 나오는 것 | 게이트 |
| --- | --- | --- | --- |
| **0. 표본 모으기** | 의사록 20건 (텍스트본 10 · 스캔본 10), 손으로 정답 작성 | 골든셋 | 반나절. **이게 없으면 나머지가 전부 감이다** |
| **1. 읽기 검증** | ①②③ 만. 모델 없음 | 페이지 분류 적중률, 텍스트 추출 품질 | 텍스트 레이어 비율이 실제로 높은가 |
| **2. 뽑기 PoC** | `parse_minutes.py` 로 20건 일괄 | JSON 20건 + 채점표 | **숫자·날짜 98%+, 의안 경계 95%+, 요약 사람평가 4/5** |
| **3. 원가 확정** | 2단계 실측 토큰으로 계산 | 건당 원가 | 6장 추정과 자릿수가 맞는가 |
| **4. 보안 승인** | 2·3 결과로 법인 검토 요청 | 허용 경로 확정 | 벽2. B안인가 C안인가 |
| **5. 화면** | 작업대 붙이기 | 좌 PDF · 우 스키마 | 검증 시간이 수작업의 1/3 이하인가 |
| **6. 엑셀** | (2단계 — 이 문서 범위 밖) | | 5 통과 후 |

**2단계에서 멈출 수 있어야 한다.** 화면을 먼저 만들면 정확도가 안 나와도 되돌리기 어렵다.
스크립트 하나로 20건을 돌려 채점표를 보는 데까지가 가장 싼 진실이다.

## 9. 미리 알고 있는 위험

| 위험 | 어디서 터지나 | 완화 |
| --- | --- | --- |
| **원문 변조** | 대화전문·의안원문 | 위치 방식(1장). 모델이 글자를 못 만든다 |
| **환각으로 없는 값 채우기** | 대화전문 없는 요약식 의사록 | `style` 플래그 + 앵커링 실패 시 폐기 |
| **정족수 오독** | "재적 7명 중 6명" 류 서술 | 명단과 대조 + 상법 규칙 (5장) |
| **회사별 양식 편차** | 의안 표기, 표 구조 | 규칙 우선·모델 보조. 규칙은 회사별로 늘린다 |
| **스캔 품질** | 날인 페이지, 기울어진 스캔 | 페이지 단위 분기 + 회전 보정. 낮은 신뢰도는 표시하고 넘기지 않는다 |
| **스키마 변경** | 2단계 엑셀 매핑 확정 시 | `schemaVersion` + 마이그레이션 함수 |
| **보안** | 전 구간 | 벽2. 무보존·무학습 티어, 메모리 처리, 본문 로깅 금지 |

법적 문서라 **누락보다 조용한 오탐이 훨씬 비싸다.** 확신이 없으면 빈칸으로 두고 `검토 필요`
를 다는 쪽이 항상 맞다. 화면도 그렇게 설계한다 — 채워진 값이 아니라 **비어 있고 표시된 값**이
사용자를 안내한다.
