## [0] 공통 정보 — 세 문서 모두에 붙여넣기

```
[프로젝트 정보: 찾붙머신 (FindPaste)]

한 줄 소개
- 회계감사 조서를 만들 때 "찾아야 하는 것들"(기준서 문단, 환율, 이자율, 이사회 의사록 내용)을
  한 자리에서 찾아, 조서 양식 그대로 엑셀에 붙여넣게 해 주는 웹 애플리케이션.
- 예전 이름은 "회계기준서 조서 추출기" → "기준서 데스크". 하는 일(찾고 붙이기)이 그대로 들리는 이름으로 바꿨다.
- 화면 용어는 네 동사로 통일: 찾는다 → 읽는다 → 담는다 → 붙여넣는다.

화면 구조
- 첫 화면에서 '작업대'를 고른다. 작업대는 모두 같은 모양이다:
  왼쪽에서 찾고 → 오른쪽 엑셀 미리보기에서 조서 모양 그대로 복사해 붙여넣는다.
- 작업대 목록과 상태
  1) 기준서 찾기 (사용 중): K-IFRS 기준서 40건 · 문단 3,661건 통합검색, 목차 트리, 본문 읽기,
     '+ 담기'로 인용함에 담아 조서 양식(기본 45자 줄바꿈, 문단제목 행 삽입)으로 붙여넣기.
  2) 환율 찾기 (사용 중): 서울외국환중개 고시 매매기준율을 통화(18개)·기간으로 조회,
     기간 평균환율·기말환율 자동 계산, 출처·기준일 각주 자동 포함, JPY·IDR·VND 100단위 고시 표시.
  3) 이자율 찾기 (사용 중): 금융투자협회 채권시가평가수익률(평가사 평균) 표를 기준일로 조회.
     용도(리스 1116호 / 충당부채 1037호 / 퇴직급여 1019호)를 고르면 근거 문단 안내와
     권장 행 음영. 만기 선형보간 옵션.
  4) 의사록 읽기 (사용 중): 이사회 의사록 PDF를 규칙(정규식)만으로 읽어 일시·장소·출석 인원·
     의안(제목·가결 여부·표결 수·결의 발췌·금액·관련 기준서 후보)을 뽑는다.
     뽑은 값마다 원문 위치를 표시하고, 오른쪽 값을 누르면 왼쪽 원문 해당 자리가 칠해진다.
     확신 없는 값은 지어내지 않고 '검토 필요'로 남긴다. 스캔 페이지는 브라우저 안 OCR.
  5) 사건번호 찾기 (준비 중): 소송충당부채·우발부채 조서용. 대법원 사건검색에 공개 API가
     없어 입력 방식부터 정해야 함.

핵심 원칙 (보안·신뢰)
- 서버 없음, API 키 없음, AI 모델 호출 없음. 사용자의 파일은 브라우저 밖으로 나가지 않는다.
  (이사회 의사록은 미공개 중요정보이므로 이 성질이 기능보다 중요하다.)
- 원문을 다시 쓰지 않는다. 의사록에서 뽑는 글자는 원문에서 잘라낸 그대로다 (증빙 가치 유지).
- 출처를 붙인다. 환율·이자율 표에는 출처와 자료 기준일이 각주로 들어간다.
- 판단은 사람이 한다. 도구는 '어디를 볼지'까지만 좁힌다.

데이터 품질 관리
- 기준서는 한국회계기준원 HWP 원문을 파싱해 만든다. 미반영: 제1109호 '금융상품'.
- '의심 문단 훑기'가 원문과 다를 것 같은 문단(현재 약 230곳)을 노란색으로 표시한다.
- '수정 모드'에서 쓰던 사람이 이름을 남기고 바로 고친다. 고친 내용은 수정 로그(.md/.json)로
  내려받아 검토 후 원본에 반영한다 (footing).
- 환율은 평일 18:30, 이자율은 평일 19:10(KST)에 GitHub Actions가 자동으로 받아 갱신한다.

의사록 읽기 정확도 (합성 표본 기준 — 실제 의사록 성능이 아님을 반드시 함께 적을 것)
- 텍스트 PDF 500건(규칙만): 100.0% (6,248/6,248 필드)
- 스캔 열화본 70건(규칙+OCR): 71.7%. 갈래별: 스마트폰 촬영 85~86%, 사무실 스캔 78~81%,
  오래된 종이 74.6%, 팩스 24.3%(원본 재요청 권장)
- 브라우저판과 파이썬판 결과 대조: 6,000건 이상에서 불일치 0건

쓰는 방법 (배포)

## [1] 개발 가이드

### 추가 정보

```
[개발자용 추가 정보]

기술 스택
- 프론트: React 19, TypeScript 5.8, Vite 6, Tailwind CSS 4, lucide-react 아이콘
- PDF: pdfjs-dist / OCR: tesseract.js (한국어+영어 모델을 사이트에서 직접 서빙, 외부 전송 없음)
- 엑셀: xlsx(SheetJS), 클립보드에 HTML 표 + TSV를 함께 넣어 서식 유지
- 데이터 수집·가공: Python 스크립트 (scripts/)
- 패키지 매니저: CI는 bun (bun install --frozen-lockfile), 로컬은 npm도 가능
- 라우팅: 주소창 해시 (#/standards, #/fx, #/rates, #/minutes, #/litigation)
- vite base: './' (Pages 하위 경로에서도 상대경로로 동작)

명령어
- npm install / npm run dev (포트 3000) / npm run build / npm run lint (= tsc --noEmit)

폴더 구조
- src/workspaces/registry.ts : 작업대 목록의 유일한 출처. 첫 화면 카드·라우팅이 이 표를 따름.
  새 작업대 = 여기에 한 줄 + src/workspaces/XxxWorkspace.tsx 화면 컴포넌트
- src/workspaces/ : StandardsWorkspace, FxWorkspace, RatesWorkspace, MinutesWorkspace
- src/components/ : 공통 UI (엑셀 미리보기 그리드, 레이아웃 조절, 인용함, 수정 모드 등)
- src/utils/ : 검색(search.ts), 텍스트 분할(textSplitter.ts), 목차(toc.ts), 시트 내보내기,
  환율·이자율 조회, 의심 문단 점검(auditStandards.ts), 수정 기록 저장(editStore.ts)
- src/lib/minutes/ : 의사록 읽기 (text.ts 좌표계, rules.ts 규칙, parse.ts, ocr.ts)
- src/data/standards/k-ifrs-XXXX.json : 기준서 (import.meta.glob으로 자동 로드, 코드 수정 불필요)
- src/data/fx/*.json : 통화별 환율 (한 줄에 하루씩 — diff로 변경을 보기 위해)
- src/data/rates/avg-YYYY.json : 연도별 시가평가수익률
- scripts/ : parse_kifrs_hwp.py(HWP→JSON), ingest_standards.py(검증+배치),
  audit_standards.py(의심 문단, 앱과 같은 규칙), apply_edit_log.py(수정 로그 반영),
  fetch_fx_rates.py + smbs.py(환율), fetch_kofia_rates.py + kofia.py(이자율),
  parse_minutes.py / minutes_rules.py / minutes_text.py / eval_minutes.py /
  make_sample_minutes.py / bench_minutes.py (의사록 파이썬판·채점)
- docs/ : footing-plan, minutes-plan, minutes-ocr, rates-plan, naming, roadmap

데이터 파이프라인 — "서버가 없다"를 우회하는 방식
- GitHub Pages 정적 호스팅이라 브라우저가 외부 사이트를 직접 못 부른다 (CORS, http 차단).
- 그래서 GitHub Actions가 외부 자료를 받아 JSON으로 저장소에 커밋하고, 앱은 저장소 JSON만 읽는다.
- 환율: smbs.biz는 셀 글자를 난독화(% 뒤 표식 한 글자)해 둠 → 떼고 unescape. EUC-KR,
  열은 머리글로 찾음, 전일대비는 아이콘을 부호로, 90일씩 끊어 묻고 빈 표는 재시도,
  8일 넘게 끊긴 구간은 로그. 기존 날짜는 두고 새 날짜만 덧붙이되 정정된 값은 덮어씀.
- 이자율: 금투협 kofiabond ProFrame XML 서비스(BISBndSrtPrcSrchSO.selectDay) POST,
  평가사 평균(A20000). 응답이 중간에 끊기는 일이 잦아 재시도.

GitHub Actions
- deploy.yml : 타입체크 → 빌드 → GitHub Pages 배포
- fx-rates.yml : 평일 18:30 KST + 수동, 최근 30일 받아 바뀐 것만 커밋
- kofia-rates.yml : 평일 19:10 KST

기준서 추가·수정 절차
1) python3 scripts/parse_kifrs_hwp.py <HWP 또는 폴더> --include-ig -o parsed_json/
2) python3 scripts/ingest_standards.py parsed_json/  (하나라도 문제 있으면 아무것도 복사 안 함)
   검사: 배열 형식, 필수 필드, category 값, id 중복, 빈 content, standardId·Code·Title 일치
3) python3 scripts/audit_standards.py --severity P1  (P1: NUM_GAP, DUP_BODY, TOO_SHORT = 배포 차단)
4) 사용자 수정 로그 반영: python3 scripts/apply_edit_log.py <로그들> → 검토, --apply로 반영
   (문단별 마지막 수정만, 원본이 '수정 전'과 다르면 반영하지 않고 표시)

의사록 정확도 재는 법
- python3 scripts/make_sample_minutes.py -o samples/minutes
- python3 scripts/parse_minutes.py samples/minutes -o out/minutes --print [--ocr tesseract]
- python3 scripts/eval_minutes.py samples/minutes out/minutes --detail
- 봉인 표본(규칙 수정 때 보지 않은 시드)으로만 성능을 말한다. 작업용 구간 숫자는 성능이 아님.
- OCR 설정: Tesseract psm 4 · kor+eng (글자 일치 80.4%, 4.8초/건). psm 6은 66.7%.
  이진화·선명화 같은 전처리는 전부 손해였음.

개발 원칙 (코드에서 읽히는 관례)
- 커밋 메시지: 한국어 conventional commit (예: feat(rates): …, chore(fx): …, docs(rates): …)
- 외부로 데이터를 보내는 코드는 넣지 않는다 (의사록 작업대의 전제). 모델·클라우드 OCR을
  붙이려면 보안 심의(학습 미사용·무보존·국외 이전)가 먼저.
- 조용히 빠지는 것이 가장 나쁘다: 실패·누락은 표시하고 멈춘다 (SCAN_PAGE, 검토 필요, 로그).
- 화면 용어는 찾는다/읽는다/담는다/붙여넣는다 밖으로 나가지 않는다.
- 저장소에 실제 의사록을 두지 않는다 (합성 표본만).
```

### 프롬프트

```
위 [프로젝트 정보]와 [개발자용 추가 정보]만을 근거로, 이 프로젝트에 새로 합류하는 개발자를 위한
노션 개발 가이드 문서를 한국어로 작성해 줘.

독자: 웹 개발은 할 줄 알지만 이 저장소와 회계감사 업무는 처음인 개발자.
목표: 이 문서만 읽고 첫날에 로컬 실행 → 구조 이해 → 작은 수정 후 배포 흐름까지 갈 수 있게.

구성 (노션 제목 H2/H3 사용):
1. 한 문단 요약 — 무엇을, 누구를 위해, 왜 이런 구조인지
2. 빠른 시작 — 설치·실행·빌드·타입체크 명령을 코드 블록으로
3. 아키텍처 — "서버가 없다"는 제약과 그 우회 방식(Actions가 받아 JSON 커밋)을 그림처럼 이해되게
   텍스트 흐름도(→)로 설명
4. 폴더 구조 — 표 (경로 | 역할 | 언제 건드리나)
5. 작업대 추가하는 법 — 단계별 체크리스트
6. 데이터 파이프라인별 설명 — 기준서 / 환율 / 이자율 / 의사록. 각각 "출처 → 가공 → 저장 위치 →
   갱신 주기 → 주의할 점"
7. 품질 관리 — 기준서 검증·의심 문단·수정 로그 반영 절차, 의사록 정확도 측정 방법
8. CI/CD와 배포 — 워크플로우 표, 릴리스 규칙
9. 개발 원칙 — 왜 그런 원칙인지 이유와 함께 (특히 외부 전송 금지, 원문 불변, 조용한 실패 금지)
10. 자주 막히는 지점 / FAQ — 정보에 근거한 것만
11. 참고 문서 목록 (docs/ 파일)

작성 규칙:
- 주어진 정보에 없는 명령어·파일·기능을 만들어 내지 마. 모르는 것은 "[확인 필요]"로 남겨.
- 명령어와 경로는 반드시 코드 서식.
- 문장은 짧고 단정하게. 마케팅 문구 금지.
- 표와 체크리스트를 적극 활용하고, 각 섹션 맨 앞에 한 줄 요약을 둬.
- 노션 콜아웃(💡 팁, ⚠️ 주의)을 섹션당 최대 하나만.

- 통합검색: 기준서를 고르지 않고 3,661개 문단 전체 검색, 기준서별로 묶어 표시, 검색어 하이라이트.
  범위를 '이 기준서'로 좁힐 수 있음. 모든 낱말이 맞는 문단이 없으면 일부만 맞는 문단을 대신 보여줌
  (예: '이용권자산'으로 검색해도 '사용권자산' 문단을 찾아 줌).
- 본문을 클릭해도 선택되지 않는다. 문단번호 옆 '+ 담기'로만 인용함에 들어감 (읽고 판단한 뒤 담기).
  본문을 드래그해 그대로 복사할 수도 있음.
- 조서 설정: 줄당 글자 수(기본 45자, 문장이 자연스럽게 끊기게 분할), 문단제목 수준
  (대분류만 / 소분류만 / 대분류 > 소분류), 시작 셀 위치(예: C26) 지정.
- 복사하면 엑셀에 붙일 때 음영·테두리가 유지됨. 엑셀 Ctrl + + (복사한 셀 삽입) 활용,
  원클릭 VBA 매크로 코드 제공. 사내 기준서 DB(JSON) 가져오기 가능.

수정 모드 (원문과 다른 문단을 발견했을 때)
- 상단 '수정 모드' → 이름 입력 → 문단의 '수정' 버튼으로 본문·제목 수정.
- 원본은 바뀌지 않고 내 브라우저에 기록이 쌓여 본문·검색·조서에 반영됨.
- '의심 문단 훑기'를 누르면 원문과 다를 것 같은 문단이 노란색으로 표시되고, 기준서 목록에 개수 배지.
- '수정 로그'에서 파일을 내려받아 관리자에게 보내면 원본에 반영됨.

환율 찾기
- 통화와 기간을 고르면 일자별 매매기준율. 담은 날짜가 오른쪽 엑셀 미리보기에 조서 모양으로.
- 기간 평균환율·기말환율 자동 계산. 출처(서울외국환중개)와 자료 기준일이 각주로 함께 붙음.
- JPY·IDR·VND는 100단위 고시 — 표 제목에 표시됨 (놓치면 100배 틀림).
- 화면에는 천단위 쉼표, 붙여넣은 값은 서식 없는 숫자라 엑셀에서 바로 계산 가능.

이자율 찾기
- 단계: ① 용도(리스/충당부채/퇴직급여) ② 기준일 ③ 종류·등급(행, 여러 개) ④ 만기(열, 여러 개)
- 용도를 고르면 근거 기준서 문단 안내와 권장 행 음영:
  리스(1116호 26·41·45문단, 회사 신용등급 회사채), 충당부채(1037호 45~47·60문단, 국고채),
  퇴직급여(1019호 83~86문단, AA 이상 우량회사채)
- 표에 없는 만기는 선형보간 옵션. 쓴 행·열에 음영이 칠해진 채로 근거 문단과 함께 붙여넣기.

의사록 읽기
- PDF를 끌어다 놓으면 왼쪽 원본, 오른쪽 뽑아낸 항목.
- 오른쪽 아무 칸이나 누르면 왼쪽 원문의 그 자리가 칠해지며 화면 가운데로 옴.
- 의안 카드: 제목·가결 여부·표결 수·결의 발췌·금액·펴 볼 기준서 후보. '의안 원문 전체 보기'로 본문 전체.
- 스캔 페이지는 처음 한 번만 OCR 엔진(8.4MB)을 받고 이후엔 저장해 둠. OCR로 읽은 값에는 'OCR' 표시
  — 원문 그대로가 아니니 반드시 원문과 대조.
- '검토 필요' 표시는 도구가 확신하지 못한 자리. 값을 지어내지 않고 비워 둔 것.
- 팩스본은 정확도가 낮다(약 24%) — 원본을 다시 받는 편이 빠름.
- 재무제표 영향 여부는 판단하지 않는다. 어디를 볼지까지만 좁혀 줌.

보안 Q&A
- 파일이 어디로 가나요? 아무 데도 안 갑니다. 브라우저 안에서만 읽습니다. 인터넷을 끊어도 동작합니다.
