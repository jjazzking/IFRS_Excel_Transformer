# 기준서 데스크 (Standards Desk)

조서를 만들 때 **찾아야 하는 것들을 한 자리에** 모으는 웹 애플리케이션입니다.

화면은 두 계층입니다.

```
첫 화면 (작업대 고르기)  →  작업대 하나
                            왼쪽에서 찾고 · 오른쪽 엑셀 미리보기에서 조서에 붙여넣는다
```

작업대는 모두 같은 모양이고, **찾는 대상만 다릅니다.** 어느 작업대에 있는지는 주소창
해시에 남으므로(`#/standards`) 링크로 바로 열 수 있습니다.

| 작업대 | 왼쪽에서 찾는 것 | 오른쪽에 담기는 것 | 상태 |
| --- | --- | --- | --- |
| **기준서 찾기** (`#/standards`) | 기준서 목록 · 목차 · 본문 | 인용함 + 엑셀 미리보기 | 사용 중 |
| **이자율 찾기** (`#/rates`) | 만기·등급·기준일로 이자율 조회 | 고른 이자율 표 + 엑셀 미리보기 | 준비 중 — 금리 데이터 출처 확정 필요 |
| **환율 찾기** (`#/fx`) | 통화·기간으로 환율 조회 | 담은 날짜 + 평균·기말 + 엑셀 미리보기 | 사용 중 |
| **사건번호 찾기** (`#/litigation`) | 법원·사건번호로 조회 | 사건 진행 내역 + 엑셀 미리보기 | 준비 중 — 대법원 사건검색은 공개 API 없음 |

작업대 목록은 `src/workspaces/registry.ts` 한 곳에 있습니다. 카드·라우팅·README 가 모두
이 표를 따르므로, 작업대를 추가할 때는 여기에 한 줄 적고 화면 컴포넌트를 붙이면 됩니다.

## 🚀 GitHub Pages 배포 방법

본 프로젝트는 GitHub Actions 자동 배포 워크플로우(`.github/workflows/deploy.yml`)가 구성되어 있어, 리포지토리에 푸시하기만 하면 자동으로 GitHub Pages에 배포됩니다.

### 1단계: GitHub 리포지토리 생성 및 코드 푸시

로컬 터미널에서 다음 명령어를 실행합니다:

```bash
# 1. git 초기화 (아직 안 되어 있다면)
git init
git add .
git commit -m "feat: 회계기준서 조서 추출기 초기 구현"

# 2. main 브랜치 지정 및 원격 리포지토리 연결
git branch -M main
git remote add origin https://github.com/<본인_아이디>/<리포지토리명>.git

# 3. 코드 푸시
git push -u origin main
```

### 2단계: GitHub Pages 소스 설정 (GitHub 웹사이트)

1. GitHub의 본인 프로젝트 저장소 페이지로 이동합니다.
2. 상단 메뉴에서 **Settings** 탭을 클릭합니다.
3. 좌측 사이드바에서 **Pages**를 클릭합니다.
4. **Build and deployment** 섹션의 **Source** 드롭다운에서 **`GitHub Actions`**를 선택합니다.
5. 상단 **Actions** 탭으로 이동하면 자동으로 빌드 및 배포가 진행되는 것을 확인할 수 있습니다. (약 1~2분 소요)
6. 배포가 완료되면 발급된 `https://<본인_아이디>.github.io/<리포지토리명>/` 주소로 접속하여 사용하시면 됩니다!

## 📋 기준서 찾기 작업대

### 3존 화면

기준서 번호를 이미 아는 경우뿐 아니라, **어떤 기준서인지 모르는 상태에서도** 찾아갈 수 있도록
화면을 좌·중·우 세 구역으로 나눴습니다. 좌우 패널은 각각 접어서 본문을 넓게 볼 수 있습니다.

| 구역 | 내용 |
| --- | --- |
| 좌 | **기준서 목록**(번호·제목·문단수, 분류 필터) ↔ **목차 트리**(본문/부록/실무적용지침 → 대분류 → 소분류, 문단 범위 표기) |
| 중 | **통합검색 결과**(검색어가 있을 때) 또는 **본문 리더**(문단 전문) |
| 우 | 조서에 담은 문단 목록 + 실시간 엑셀 미리보기 + 복사/추출 |

**폭 조절**: 구역 사이의 경계를 드래그하면 폭이 바뀌고, 더블클릭하면 그 패널만 기본 폭으로
돌아갑니다. 정한 폭은 브라우저에 남아 다음에 열 때 그대로 쓰입니다. 좌·우 패널은 접을 수 있고,
접히면 세로 띠만 남아 눌러서 다시 펼칩니다. 창을 좁혀도 본문이 최소 폭 아래로 눌리지 않도록
오른쪽부터 차례로 폭을 양보합니다.

**프리셋** 세 가지로 한 번에 배분을 바꿀 수 있습니다.

| 프리셋 | 배분 |
| --- | --- |
| 탐색 | 목차와 본문을 넓게, 엑셀은 접음 |
| 균형 | 세 구역을 기본 폭으로 |
| 조서 | 탐색을 접고 엑셀 미리보기를 최대로 |

- **전 기준서 통합검색**: 기준서를 먼저 고르지 않고 3,661개 문단 전체에서 찾습니다. 결과는
  기준서별로 묶여 나오고, 검색어가 하이라이트된 미리보기에서 바로 조서에 담거나 본문으로 건너뜁니다.
  검색 범위를 `이 기준서`로 좁힐 수도 있습니다.
- **부분일치 대체 결과**: 모든 낱말이 다 들어간 문단이 없으면(예: 기준서는 '사용권자산'인데
  '이용권자산'으로 검색) 빈 화면 대신 일부 낱말만 맞는 문단을 보여줍니다.
- **목차 트리**: 별도 목차 데이터 없이 문단의 `sectionTitle`/`subTitle` 과 문단번호에서 만들어집니다.
  본문을 스크롤하면 지금 읽는 위치가 목차에서 강조됩니다.
- **읽기와 담기 분리**: 본문을 클릭해도 선택되지 않습니다. 문단번호 옆 `+ 담기` 버튼으로만
  조서에 들어가므로, 읽어보고 판단한 뒤 담을 수 있고 본문을 드래그해 그대로 복사할 수도 있습니다.

### 조서 만들기

- **문장 보존형 스마트 텍스트 분할**: 지정한 글자 수(기본 45자) 단위로 문맥과 단어가 자연스럽게 연결되도록 다음 행에 배분
- **문단제목 수준 선택**: 대분류만 / 소분류만 / `대분류 > 소분류` 중 선택하고, 문단제목이 바뀌는 위치마다 제목 행을 다시 삽입
- **상대 위치(A1, B1 등) 매핑**: 엑셀 조서의 특정 셀(예: C26)을 기준으로 순수 내용만 추출
- **엑셀 서식 클립보드 복사**: HTML Table 및 TSV를 동시에 클립보드에 담아 엑셀에 붙여넣을 때 음영/테두리 서식 유지
- **엑셀 단축키 및 VBA 매크로 지원**: `Ctrl + +` (복사한 셀 삽입) 및 원클릭 매크로 코드 제공
- **사내 DB 가져오기**: JSON 형태의 사내 기준서 DB 즉시 임포트 기능 제공

## 💱 환율 찾기 작업대

외화환산 조서에 쓰는 **매매기준율**을 통화와 기간으로 뽑아 조서에 그대로 붙입니다.
자료는 [서울외국환중개](http://www.smbs.biz/ExRate/StdExRate.jsp) 고시 환율입니다.

### 결산기 바로 담기 (기본)

감사에서 환율이 필요한 자리는 정해져 있습니다. 통화·결산월·회계연도를 고르고
**`1분기말` `반기말` `3분기말` `기말`** 중 하나를 누르면 이 여섯 줄이 한 번에 섭니다.

| 구분 | 적용 기준일 / 기간 | 환율 | 고시일수 |
| --- | --- | --- | --- |
| 당기 마감환율 | 2025-09-30 | 1,402.20 | |
| 당기 평균환율 (누적) | 2025-01-01~2025-09-30 | 1,412.79 | 183 |
| 당기 평균환율 (당분기) | 2025-07-01~2025-09-30 | 1,385.28 | 65 |
| 전기 마감환율 | 2024-09-30 | 1,319.60 | |
| 전기 평균환율 (누적) | 2024-01-01~2024-09-30 | 1,352.85 | 183 |
| 전기 평균환율 (당분기) | 2024-07-01~2024-09-30 | 1,359.38 | 62 |

- **결산월**을 고를 수 있습니다. 3월 결산 2026년이면 2025-04-01 에 시작해
  2026-03-31 에 끝나고 1분기말은 2025-06-30 입니다.
- 평균환율이 **누적**과 **당분기**로 나뉩니다. 반기 손익은 1/1~6/30 누적으로
  환산하지만 분기 비교에는 당분기 평균이 필요합니다. 1분기말은 둘이 같아 한 줄만 나옵니다.
- 결산일이 **주말·휴장**이면 직전 고시를 쓰되 *어느 날 고시를 썼는지* 표에 적습니다.
  12월 31일이라고만 적고 실제로는 29일 고시를 쓴 것이 드러나지 않으면 리뷰에서 되돌아옵니다.
- 결산일이 **아직 오지 않았으면 마감환율을 비워 둡니다.** 직전 고시를 내주면 오늘
  환율이 기말환율로 조서에 오릅니다. 진행 중인 평균은 어디까지의 평균인지 함께 적습니다.
- 자료가 요구한 기간보다 늦게 시작하면 짧아진 구간을 적고 각주로 알립니다.

왼쪽 일자별 표는 누적 구간에 맞춰지고 마감환율로 쓰인 행이 표시됩니다. 평균이 어느
날들로 계산됐는지 눈으로 확인할 수 있습니다.

### 직접 조회

결산기에 없는 구간이 필요하면 날짜를 직접 넣어 하루씩 담습니다.

공통으로 지켜지는 것들입니다.

- **100단위 고시**(JPY·IDR·VND)는 표 제목에 드러냅니다. 빠지면 100배 틀립니다.
- **출처와 자료 기준일**이 표 각주로 함께 들어갑니다. 출처 없는 환율은 리뷰에서 되돌아옵니다.
- 붙여넣은 값으로 계산을 이어 갈 수 있도록, 화면에는 천단위 쉼표를 넣되 클립보드에는
  서식 없는 숫자를 넘깁니다.

### 자료는 어떻게 들어오는가

이 앱은 GitHub Pages 정적 호스팅이라 **브라우저가 smbs.biz 를 직접 부를 수 없습니다.**
CORS 에 막히고, 사이트가 `http` 라 `https` 페이지에서는 아예 차단됩니다. 그래서 기준서
JSON 과 같은 방식을 씁니다 — GitHub Actions 가 받아 저장소에 커밋하고, 앱은 저장소 안의
JSON 만 읽습니다.

| 워크플로우 | 언제 | 무엇을 |
| --- | --- | --- |
| `.github/workflows/fx-rates.yml` | 평일 18:30 KST · 수동 실행 | 최근 30일치를 받아 바뀐 것이 있으면 커밋 |

```bash
python3 scripts/fetch_fx_rates.py                       # 기본 통화 17개, 최근 3년
python3 scripts/fetch_fx_rates.py --currencies USD,JPY --days 60
python3 scripts/fetch_fx_rates.py --from 2024-01-01 --to 2024-12-31
python3 scripts/fetch_fx_rates.py --all-currencies      # 고시되는 통화 전부
```

받아 둔 날짜는 그대로 두고 새 날짜만 덧붙입니다. 같은 날짜가 다시 오면 새 값으로
바꿉니다 — 사이트가 값을 정정하는 경우가 있습니다.

### 사이트를 읽는 방법 (`scripts/smbs.py`)

이 사이트는 표의 글자를 그대로 두지 않습니다. 모든 셀이 자바스크립트 호출 안에 있고,
브라우저가 그 함수를 돌려야 글자가 나옵니다. 난독화는 간단합니다 — `%` 또는 `%u` 뒤에
의미 없는 표식 한 글자가 끼어 있고, 그것만 떼면 `unescape` 와 같은 형식입니다.

```
%_Z32%_Z30%_Z32%_Z36  →  2026
%u_Zc77c%u_Zbcf8      →  일본
```

| 다루는 것 | 왜 |
| --- | --- |
| 응답을 EUC-KR 로 읽는다 | 페이지 인코딩이 그렇다 |
| 열을 자리가 아니라 **머리글로 찾는다** | USD 는 시가·고가·저가까지 열 개, 나머지 통화는 Cross Rate 까지 다섯 개다 |
| 전일대비를 **부호로 바꾼다** | 오르내림이 숫자가 아니라 옆의 아이콘에 있다. 숫자만 남기면 방향이 사라진다 |
| 90일씩 끊어 묻고, 빈 표는 세 번 더 묻는다 | 긴 기간을 물으면 표가 통째로 비어 오는 일이 잦다 |
| 8일 넘게 끊긴 자리를 로그에 적는다 | 설·추석 연휴도 영업일로는 5일 남짓이다. 조용히 빠지는 것이 가장 나쁘다 |

저장 형식은 통화별 JSON 한 파일이고, **한 줄에 하루씩** 적습니다. 기본 들여쓰기로는
하루가 열 줄이 되어 diff 로 무엇이 바뀌었는지 볼 수 없습니다.

## 🗂️ HWP 기준서 원문 → 기준서 DB 변환

한국회계기준원에서 배포하는 기준서 HWP(한글 5.0) 파일을 애플리케이션의 기준서 DB
스키마(`src/types.ts` 의 `AccountingStandard[]`)에 맞는 JSON으로 변환하는 스크립트입니다.

```bash
pip install -r scripts/requirements.txt

# 기본: 기준서 본문(문단 1~140 및 '한' 문단)만 추출
python3 scripts/parse_kifrs_hwp.py 기업회계기준서_제1001호.hwp -o src/data/standards/k-ifrs-1001.json

# 실무적용지침(IG)도 같은 기준서의 문단으로 함께 추출
python3 scripts/parse_kifrs_hwp.py 기업회계기준서_제1001호.hwp --include-ig -o out.json

# 추출된 원문 텍스트를 확인하고 싶을 때
python3 scripts/parse_kifrs_hwp.py 기업회계기준서_제1001호.hwp --dump-text raw.txt

# 폴더 통째로 변환 — 기준서 번호를 읽어 k-ifrs-<번호>.json 으로 자동 저장한다.
# 한 파일이 실패해도 나머지는 계속 진행하고, 끝에 실패 목록을 보여준다.
python3 scripts/parse_kifrs_hwp.py ~/기준서_HWP/ --include-ig -o parsed_json/
```

### 파싱 방식

| 단계 | 처리 내용 |
| --- | --- |
| 1. 텍스트 추출 | OLE 복합문서에서 `BodyText/Section*` 스트림을 zlib 해제 후 `HWPTAG_PARA_TEXT` 레코드만 디코딩 |
| 2. 목차 분석 | 목차의 제목 목록과 문단번호 범위를 짝지어, 범위 포함관계로 제목의 계층(level)을 계산 |
| 3. 본문 파싱 | `문단번호 + 탭/공백 + 본문` 패턴으로 문단을 분리하고, ⑴ ㈎ 등 하위 항목은 `\n` 으로 이어붙임 |
| 4. 메타데이터 | 계층 경로에서 `sectionTitle`(상위 제목) / `subTitle`(최하위 제목)을 부여하고, 회계 용어 사전 기반으로 `keywords` 생성 |

### 산출물

`src/data/standards/` 아래 JSON 40개 파일에 **기준서 40건 / 문단 3,661건**이 들어 있습니다.
실무적용지침(IG)은 별도 기준서가 아니라 상위 기준서의 문단(`IG1`, `IG5A` …)으로 들어갑니다
— 제1001·1101·1102·1107·1108호가 이에 해당합니다.

아직 반영되지 않은 기준서: 제1109호 '금융상품'(다단계 문단번호 대응 후 재파싱 필요).

#### 기준서 추가 방법

`src/data/standards/` 폴더에 **JSON 파일만 넣으면 됩니다.** 코드 수정은 필요 없습니다.
`standardsData.ts` 가 `import.meta.glob` 으로 해당 폴더의 `*.json` 을 전부 자동으로 읽어들입니다.

- 파일명 규칙: `k-ifrs-XXXX.json` (파일명 오름차순으로 목록에 표시됨)
- 파일 형식: 기준서 **배열** `[{ "id": ..., "paragraphs": [...] }]`
- `id` 는 다른 기준서와 겹치지 않아야 합니다

검증까지 함께 하려면 배치용 스크립트를 쓰면 됩니다. 문제가 하나라도 있으면
아무 파일도 복사하지 않고 무엇이 잘못됐는지 알려줍니다.

```bash
# 디렉터리째 검증 + 배치
python3 scripts/ingest_standards.py ~/parsed_json/

# 검증만
python3 scripts/ingest_standards.py ~/parsed_json/ --check-only
```

검사 항목: 배열 형식 / 기준서·문단 필수 필드 / `category` 유효값 /
기준서·문단 id 중복 / 빈 `content` / 문단의 `standardId`·`standardCode`·`standardTitle` 일치.

## ✅ 기준서 수정 모드와 footing

파싱된 기준서가 원문과 다를 때, **쓰던 사람이 그 자리에서 고치고 기록을 남깁니다.**

### 앱에서 고치기

상단 **`수정 모드`** 버튼 → 이름 입력 → 문단마다 나타나는 **`수정`** 버튼으로 본문과
문단제목을 고칩니다. 원본 JSON 은 바뀌지 않고, 고친 내용은 브라우저에 수정 기록으로
쌓여 본문·검색·조서에 덧씌워집니다. **`수정 로그`** 에서 두 파일을 내려받습니다 —
검토용 `.md` 와 반영용 `.json`.

### 어디를 봐야 하는지

수정 모드 띠의 **`의심 문단 훑기`** 를 누르면 앱이 그 자리에서 전 기준서를 점검해,
원문과 다를 것 같은 문단을 **노란색으로 표시**합니다. 기준서 목록에는 기준서별 의심 지점
수가 배지로 붙고, `목록` 을 누르면 규칙별로 걸러 보며 해당 문단으로 바로 건너뜁니다.
고치면 그 표시는 저절로 사라집니다 — 다시 검사하기 때문입니다.

같은 점검을 터미널에서도 돌릴 수 있습니다 (`src/utils/auditStandards.ts` 와 같은 규칙).

```bash
python3 scripts/audit_standards.py          # 확인지점 230곳과 기준서별 분포
python3 scripts/audit_standards.py --severity P1   # 배포 차단 항목만
```

| 심각도 | 규칙 | 의미 |
| --- | --- | --- |
| P1 | `NUM_GAP` `DUP_BODY` `TOO_SHORT` | 배포 전 반드시 해소 (파서 수정이 필요할 수 있음) |
| P2 | `HEADING_LEAK` `OVERSIZE` `TAIL_NOISE` | 원문과 대조해 판단 후 수정 모드에서 수정 |
| P3 | `NO_TERMINAL` `NO_SECTION` | 참고 (기본 출력에서 제외) |

### 수정 기록을 검토하고 반영하기

```bash
python3 scripts/apply_edit_log.py ~/Downloads/standards-edit-log-*.json          # docs/edit-log.md 생성
python3 scripts/apply_edit_log.py ~/Downloads/standards-edit-log-*.json --apply  # 원본에 반영
```

여러 사람의 기록을 한 번에 받아 문단별로 마지막 수정만 반영하고, 원본이 기록의 '수정 전'과
다르면 반영하지 않고 검토 문서에 표시합니다.

자세한 절차는 [`docs/footing-plan.md`](docs/footing-plan.md) 에 있습니다.
함께 볼 문서: [`docs/naming.md`](docs/naming.md) (기능 작명) ·
[`docs/roadmap.md`](docs/roadmap.md) (확장 구상).
